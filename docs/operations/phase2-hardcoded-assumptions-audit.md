# Phase 2: Hard-coded assumptions audit

**Scope:** Complete repository audit against PRD v3.0 / merged PR #30 direction — _Default bizOS ERP
with optional customization_.  
**Date:** 2026-07-28  
**Method:** Static code and ADR review (grep + targeted file reads). No code changes.

**Target default path:** Customer → Quotation → Sales Order → Delivery/Service → Invoice → Payment →
Credit Note  
**Current universal path encoded in code:** Customer → Quotation → Customer PO → Approval Evidence →
Ready to Invoice → Invoice

## Release-blocking summary

The following **must change** to deliver the Default ERP foundation (assign configuration, allow
non–PO-invoice paths, stop encoding the specialized workflow as universal):

### Critical path (items 9, 25–27, 34–35)

1. **Configuration assignment on business create** — `platform.service.ts` must assign
   `Default bizOS ERP v1` (or equivalent) and persist `BusinessConfigurationAssignment` +
   `DocumentWorkflowContext` schema (#25, #26, #27).
2. **Configuration data model** — Prisma tables for templates, versions, assignments (#26, #35).
3. **Default ERP document entities** — At minimum Sales Order (and wiring to invoice) before
   PO-gated invoice remains the only path (#20, #34).

### Specialized workflow must stop being universal (items 1, 4, 8)

4. **Invoice origin** — Remove PO/`READY_TO_INVOICE` as the only create path; add
   configuration-gated alternatives (#1, #5, #6, #7, #8).
5. **Readiness rules** — Replace global `derivePurchaseOrderReadiness` / `bestReadiness` with
   configuration-derived rules (#2, #3, #4).

### UI and lifecycle encoding (item 8)

6. **Navigation and onboarding** — Module nav and setup steps must come from assigned configuration,
   not fixed Quotation → PO → Invoice (#11, #12, #13, #15, #16, #17).
7. **Workflow stages in services** — Status transitions and next-action CTAs must not be hard-coded
   per document type (#9, #10, #21, #22).
8. **Tests** — Add Default ERP journey coverage; keep specialized config as a named template test
   (#30, #31).

### Explicitly **not** release-blocking for this foundation (Phase 9/10)

- **Platform System Admin** role and portal (#32) — gap acknowledged; tenant `OWNER`/`ADMIN` are
  **not** currently treated as platform admin (no escalation path exists).
- **Full guided onboarding questionnaire** (#33) — default skip should auto-assign Default ERP.
- **Permission matrix from configuration** (#23) — needed before multi-configuration production, not
  first assignment.
- **Marketing copy** (#14) and **readiness CSS** (#18).
